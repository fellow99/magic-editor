## 1. 测试范围

**纳入**：函数树渲染、搜索、分组 CRUD、函数 CRUD（新建/复制/删除/锁定/解锁/路径复制）、拖拽移动、循环引用校验、排序与折叠、编辑器联动 (`open` / `position-function`)、JavaClass 函数发现器注册、Alt+G 快捷键、bus 事件订阅。

**排除**：函数脚本编辑（001）、脚本解析（011/012）、运行/调试（008/009）、`magic-group-choose` 内部行为（006）。

---

## 2. 环境前置

| 项 | 期望 |
|---|---|
| 后端 | `group/list?type=2`、`function/list` 等可访问 |
| 数据 | 至少有 1 个分组 + 嵌套子分组 + 若干函数 + 1 个根级函数 |
| 全局 | bus、`contants.SERVER_URL`、`JavaClass` 对象就绪 |
| 通用 | MagicTree、MagicDialog、`$magicConfirm`、`$magicContextmenu` 已注册 |

### E2E 跨模块数据隔离

#### TC-004-120 函数分组创建与 API 分组数据隔离
- **关联**：FR-004-004、FR-003-001、FR-101-RES-01、US-004-04
- **优先级**：P0
- **前置**：接口树中已有至少 2 个分组（如 `test1`、`test2`）；函数树初始为空；后端 file 模式
- **步骤**：
  1. 切换到左侧"函数"栏目
  2. 点击"新建分组"，填写名称 `test3`，点击"创建"
  3. 验证 `test3` 出现在函数树中
  4. 检查数据目录：`/tmp/magic-api-data/function/test3/group.json` 存在
  5. 刷新浏览器页面
  6. 验证"函数"栏目中 `test3` 正常显示
  7. **切换回"接口"栏目**，验证接口 `test1`、`test2` 分组仍然正常显示
  8. 检查数据目录：`api/test1/`、`api/test2/`、`function/test3/` 部署分离正确
- **预期**：函数分组创建不影响 API 分组数据；不同资源类型文件部署隔离

#### TC-004-121 函数分组创建后刷新完整性
- **关联**：FR-004-004、FR-004-030、FR-101-RES-01
- **优先级**：P0
- **前置**：已存在函数分组（如 `test3`）
- **步骤**：
  1. 刷新浏览器页面
  2. 切换到"函数"栏目
  3. 验证所有函数分组均正常显示
  4. 检查数据目录文件完整性
- **预期**：刷新后函数树数据不丢失

## 4. 边界与异常

| 编号 | 场景 | 预期 |
|---|---|---|
| TC-004-200 | 分组 type='1' 数据混入 | 仅渲染 type='2'（C-004 待澄清） |

| TC-004-203 | 同名分组创建 | 后端 4xx，前端提示 |
| TC-004-204 | 复制路径 execCommand 失败 | alert 显示路径 |

| TC-004-206 | 拖拽中 ESC 中断 | 不发请求 |
| TC-004-207 | 多次连续 `position-function` | 后到生效 |
